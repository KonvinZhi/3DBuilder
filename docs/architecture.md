# 工程现状

当前只有项目约定、文档、PowerShell 检查脚本和 GitHub CI 配置，没有应用、数据库、API、登录权限实现或部署环境。模型引擎、应用技术栈和硬件方案尚未选定。

## 当前阶段的文档边界

产品范围、候选构想、业务约束及待讨论问题统一保存在 [product.md](product.md)。候选交互与角色分工不作为已接受的技术决策。

本文件只记录实际工程状态。进入实现阶段后，随代码更新接口、数据、认证和部署边界。目前 `design/` 与 `plans/` 仅有 `.gitkeep` 占位文件，没有设计或执行记录。建档条件见 [文档入口](README.md)。

| 组成 | 当前实际内容 |
| --- | --- |
| `src/`、`tests/` | 仅占位文件，没有业务代码或应用测试 |
| `scripts/` | 仓库检查脚本及临时副本回归自检 |
| `.github/` | Windows / Linux 检查配置、依赖更新配置、PR 说明模板 |
| `docs/` | 产品事实、实际工程状态、文档维护规则及空的设计与计划目录 |
| `.agents/skills/` | 按需使用的第三方技能，不属于应用实现 |

## 已有工程检查

本地与 [CI](../.github/workflows/ci.yml) 使用根 [README 的检查命令](../README.md)。检查器只读取自有骨架文件；自检在系统临时目录验证检查器的正常与失败路径。检查器不能判断业务事实、设计可行性或验证证据的充分性。

CI 配置覆盖 Windows / Linux，令牌仅请求 `contents: read`，checkout 不保留凭据。2026-09-30 的 [GitHub Actions](https://github.com/KonvinZhi/3DBuilder/actions/runs/36677529190) 已在这两个系统上通过仓库检查和检查器自检。首次加入应用代码时，再接入真实启动、构建、静态检查和行为测试。

首次实现时必须验证实际的数据访问、失败处理和本地运行行为；接入商业模型时验证外发授权与费用边界。约束的主要维护位置是 [产品文档](product.md)。
